# Domo Export to S3

Operating notes for the **Domo "Export to S3 API"** — a tiny 2-operation surface that pushes a DataSet's rows to a **customer-controlled AWS S3 bucket** (asynchronously) and reads back the export's status. The `POST` takes **raw AWS credentials inline in the request body**, runs async, and writes data OUT of Domo; the `GET` polls the resulting export status. Read this before touching any `/api/query/v1/export/...` call, or any code mentioning `ExportRequest`, `awsAccessKey`/`awsAccessSecret`, `queryRequest`, `exportId`, `exportStatus`, or `urlRowCountMap`.

## What this skill owns (and defers)

- **Owns**: the REST **Export-to-S3 API** surface — the first-party spec artifact `export.yaml` (info.title "Export to S3 API", v1), host `https://{instance}.domo.com` (contested — see auth/host), the single path `/api/query/v1/export/{DATASOURCE_ID}` with its 2 ops (POST Create Export, GET Export Status), and the `ExportRequest` / `QueryRequest` / `QueryDefinition` / `QueryColumn` / `ExportStatus` / `UrlRowCountMap` / `ErrorResponse` schemas.
- **Defers**: the **synchronous inline CSV/query download** at `/api/query/v1/execute/export/{id}` (the `/execute/` sibling, `{sql}`-body driven) → `domo-datasets.md` / `domo-beast-mode.md`. **DataSet SQL query** (`/api/query/v1/execute/{id}`) and **Beast Mode** (`/api/query/v1/functions`) → their own skills. **Federated migration** (`/api/query/migration/...`, rank-16) → `domo-federated.md`. The **"Amazon S3 Unload / S3 AssumeRole Writeback Connector"** (a Datacenter connector with a Client-ID/Secret + stored-credential pane, scheduled) → `domo-accounts-connectors.md` — that is a DIFFERENT mechanism from this REST API (see naming traps). **AppDB standard-sync materialization** (`/api/datastores/v1/export/{id}`) → `domo-appdb.md` — a FALSE FRIEND, different service root.

A **single-world small island as MODELED** (1 path `/api/query/v1/export/{DATASOURCE_ID}`, 2 ops, 1 host, 1 declared auth scheme) — but distinctively a **FIRST-PARTY DOCUMENTED MIRROR-PAIR**: the candidate is byte-identical to Domo's published `product/export.yaml`, while a second independently-authored first-party spec (dev-portal `S3-Export-API.yaml`) documents the SAME single path + SAME 2-verb set yet **disagrees** on auth, host, the `exportStatus` enum, and body fields. 1. **`compression` / `exportFormat` are allowed-value-documented — CORRECTS the product-scoped "NO enum" reading.** The portal `ExportStatus` prose says `compression` "Allowed values are `none`, `gzip`" and `exportFormat` "Allowed values are `csv`". 2. **Credentials are documented one-time / not-stored / short-term — CORRECTS "long-lived static".** The portal `awsAccessKey` / `awsAccessSecret` / `awsKmsKey` / `sessionToken` prose each states the value "is used one time and is not stored in the system" and "the client should use short term or one time credentials". 3. **Temp-cred → session-token conditional rule.** Portal Security-Considerations prose: "use temporary AWS credentials whenever possible; if the credentials are temporary you must also provide an AWS session token." 5. **Object-key template + `path`/`bucket` defaults — CONTESTS product-spec required-ness.** Portal `requestBody` prose: the exported object key follows the template `<bucket>/<path>/<exportId>/export/data.csv.gz` (angle-bracket placeholders are the spec's own). `path`: if omitted, defaults to the dataSourceId. `bucket`: if omitted, a Domo-configured customer bucket is used, and the bucket **must already exist** (Domo does not create it). 6. **Timestamp representation contested — ms-epoch vs `date-time`.** Portal prose declares `started`/`finished` as "Time in milliseconds since midnight January 1, 1970" — **ms-epoch strings** — whereas the product spec types them `date-time` (ISO-8601). ## Safety & hygiene

**HIGH-SENSITIVITY — gate on explicit human intent.**

- **Credentials-in-body**: the POST `ExportRequest` REQUIRES raw AWS credentials (`awsAccessKey` + `awsAccessSecret`) inline as plaintext string fields `[DOC, unmarked core fields]` — secrets travel in the request payload and are exposed to proxy/access logging, retries, and accidental commit. **Never log, echo, or commit them; use placeholders** (`<AWS_KEY>`/`<AWS_SECRET>`/`<BUCKET>`/`<PATH>`/`<REGION>`, as the spec's own example does). **The portal spec (rank-76) documents these creds as one-time / not-stored / short-term — NOT long-lived static keys (see § portal deltas #2/#3)**; prefer temporary/STS credentials with a `sessionToken` (portal-declared; conditionally required when the creds are temporary) IF a live call confirms that field is honored (the product spec's `awsSessionToken` is commented-out/`[INFER]`).
- **Mutating + data-egress**: the POST writes DataSet rows to a **customer-controlled external S3 bucket** — an egress path OUT of Domo. Treat any invocation as a data-exfiltration-capable action requiring explicit authorization, not a routine read.
- **Async footgun**: HTTP `200` does NOT mean a file landed in S3 (it may return a PRIOR export's info when data is unchanged). Completion must be **polled via GET and confirmed by `exportStatus`**, not by the POST status code.
- **Access control** (portal `[DOC]`): the caller needs at least READ access to the DataSet and any PDP row-level policies are enforced during export — but do not assume this is the only gate.
- **Cross-region unsupported** (portal `[DOC]`): the `region` in the payload must match the bucket's region.
- **Concurrency**: only one active export per DataSet is declared — do not fire concurrent exports.
- **First live attempt**: zero executed calls + contested auth/host mean any first live attempt should be a **low-blast dry run against a non-production dataset with throwaway/scoped AWS creds**. Live-verify, in order: (a) auth (dev-token vs Bearer vs SID); (b) host (`{instance}.domo.com` vs `api.domo.com`); (c) the real `exportStatus` value set; (d) whether any 4xx/5xx actually emit; (e) idempotency mechanics (what a second POST does while an export is active); (f) whether `sessionToken`/`awsKmsKey`/`source` (portal-only fields) are honored.
