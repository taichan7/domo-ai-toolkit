# 配布品質と適用範囲

[English](distribution-readiness.md)

合成データで配備できる教材・参照実装です。本番倉庫システムや複数顧客を同居させるサービスとしての
認定ではありません。顧客ごとに独立したDomo環境へ配備し、保守用の状態や認証を共有しません。

## 配布の契約

- 公開toolkitの `main` にあるソースコードを使います。
- 配布manifestはデザインIDを省略し、接続IDを空にします。配備・`sync-manifest` 後にpublishします。
- スナップショットのUUIDは一貫した例示用IDへ置換します。Domo共通ユーティリティのpackage IDは維持します。
- `domo-assets.json`・sandbox state・認証情報・セッション・キャッシュ・生のエクスポートは除外します。
- 接続先を明示します。認証付き配備通信は外部originとredirectを拒否します。検証は名札を付け、
  本番名での配備は `INVENTORY_ALLOW_PRODUCTION=1` を明示します。
- vendorのライセンス通知を保持します。各アプリは単独で配布できる構成を維持します。

## 検証の範囲

オフラインテストは入力検証・管理権限・重複要求・HTMLエスケープ・確認/取消・QR補助・配備・名札隔離を
確認します。保守担当者のローカル状態には依存しません。

配布先では再構築ランブックを実行し、`verify` の `ok: true` を確認します。利用者/グループ、
AppDB・DataSet・カードの共有、通知宛先と実配送、AI機能/消費、想定件数、実機カメラ/QRを検証します。
ブラウザへ管理者の認証情報を埋め込みません。

## 本番適用の限界

残高投影・request_id検索・取引作成は別操作であり、原子的な在庫引当や分散ロックを提供しません。
並行要求が同じ更新前の在庫を読む可能性があります。同時更新がある本番用途では、トランザクションを
保証する書き込み基盤への置換または検証と、追記台帳からの残高照合が必要です。

同じ配備のコレクションは許可された利用者で共有します。名札は配備を分けますが、配備内の行権限を
代替しません。実データ投入前に共有/PDP・保持期間を定義し、バックアップと復旧を検証します。
SEEDはデモ専用です。AIコメントは機械確定した在庫イベントを補助するものです。
DataSetのPDPはAppDBの行権限を代替しません。利用者ごとに在庫を分ける場合は、
サーバー側の行認可またはコレクション分離が必要です。
