# 配布品質と適用範囲

[English](distribution-readiness.md)

合成の店舗損益データを使う教材・参照実装です。会計の締め処理システムや複数顧客同居サービスとしての
認定ではありません。顧客ごとに独立したDomo環境へ配備・検証します。

## 配布の契約

- 公開toolkitの `reference-architectures/pl-summary-app/` のソースを使います。保守フォルダやローカル台帳は配布しません。
- 配布manifestはデザインIDを省略し、接続IDを空にします。データ層→Workflow/CE→alias同期→publish→
  埋込context同期の順に配備します。
- スナップショットのUUIDは例示用IDへ一貫置換します。Domo共通package IDは維持します。
  `dataflow/2042.json` は履歴由来のファイル名であり、配備先のDataFlow IDではありません。
- ローカル台帳・sandbox state・認証/セッション・キャッシュ・顧客の生データを除外します。
  同梱ランタイムのライセンス通知を保持します。
- 接続先と `PL_SANDBOX_SUFFIX` を明示します。本番名での書込みは全インスタンスで
  `PL_ALLOW_PRODUCTION=1` が必要です。旧WF削除には `PL_WF03_MODEL_ID` の明示も必要です。

## 検証の範囲

オフラインテストは保存検証・新しいレポートの保護・HTML許可リスト・ドリルダウン・手動開始/取消・
配備・キャンバス配置・名札隔離を確認します。保守用のローカル台帳には依存しません。

配布先でデプロイ・ランブックを実行し、接続・release pin・権限・AIモデル/消費・全レポートの生成と
実際のメール宛先/配送を確認します。店舗選択は閲覧だけで、手動生成は全店舗＋全社が対象です。
親Workflowの定期スケジュールは作成しません。

## 本番適用の限界

実財務データ投入前に、勘定レベル・二重計上回避・会計期間・予算・通貨・組織別共有/PDPを確認します。
サンプルの会計定義を他社の帳簿にそのまま適用しません。
店舗セレクターは表示フィルターです。AppDBレポートは許可されたアプリ利用者で共有し、
DataSetのPDPでは保護されません。店舗/部門別の閲覧制限にはサーバー側の行認可またはコレクション分離が必要です。

手動開始の重複抑止は分散ロックではありません。AppDB保存と旧版掃除も別操作で、掃除が未完了になる
場合があります。監視・バックアップ・復旧試験が必要です。AI文章は誤る可能性があり、財務承認を代替しません。
HTML許可リストを維持し、実機/アクセシビリティ・並行実行・負荷・機能利用可否・メール配送を配布先で検証します。
