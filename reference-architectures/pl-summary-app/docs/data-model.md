# データモデル（店舗別損益AIインサイト）

[配布品質チェック](distribution-readiness.ja.md)は、実財務データを載せる前に会計レベル・二重計上規則・
会計期間・予算の意味・通貨・PDP を**検証せよ**と命じます。本書はその照合対象＝サンプルの会計モデルを
書き下します。各列・式の**正本**はコード／スキーマ側（下記リンク）にあり、本書はそれを consolidate したものです。

## 出力 DataSet（DataFlow が発行する4本）

| alias | 日本語 | 粒度 | 主な列（正本スキーマ） |
|---|---|---|---|
| `summary` | 要約 | 店舗 × 期間 × シナリオ | 総売上／総費用／純利益／利益率／前月比利益変化率／**状態ラベル**／カテゴリ別売上／費目別費用。全49列は [`dataset/summary.schema.json`](../dataset/summary.schema.json) |
| `detail` | 明細 | 勘定科目行（店舗 × 期間 × 勘定科目） | 勘定科目ID／名／種類／サブタイプ／**勘定科目レベル**／部門／売上金額／費用金額／利益／損失／純額／予算差異／差異率。全列は [`dataset/detail.schema.json`](../dataset/detail.schema.json) |
| `trend` | トレンド | 店舗（または全社）× 期間推移 | 期間系列の売上・利益など。**勘定科目レベル1（サマリ勘定）**を使い二重計上を避ける |
| `dept` | 事業部 | 事業部 × 期間 | 事業部別の売上・原価。**原価は勘定科目レベル2（詳細勘定）**を使う |

FE（Pro Code）はこの4本を alias で直読し、KPI・チャート・短文 AI サマリーを描く。列の追加・改名は
スキーマ（正本）と DataFlow、必要なら manifest の alias を揃えて行う。

## 会計レベルと二重計上の回避
勘定科目は階層を持ち、`detail` の **`勘定科目レベル`** 列が 1（サマリ勘定＝親）/ 2（詳細勘定＝子）を表す
（`dataflow/pl_data_generator.py` が合成）。親（レベル1）と子（レベル2）を同じ集計に混ぜると二重計上になる。
そのため **トレンドはレベル1、事業部別原価はレベル2** と使い分ける。間接費は事業部へ配賦せず、事業部別は
直課ぶんで比較する（配賦を伴う指標は定義が分かれるため、サンプルは非配賦で統一）。

## 状態ラベル（利益率で機械的に確定・LLM は再判定しない）
状態ラベルは DataFlow `2042` の SQL タイル `SQL｜要約集計（店舗×月）` の `CASE` 式が**正本**で、`summary`
出力の `状態ラベル` 列として保存される。短文（ETL）・長文（AppDB）の両 AI はこの列を**そのまま転記**し、
境界判定を LLM に委ねない（モデル間でラベルが食い違わないための一貫性コントラクト。詳細は
[prompt_shared_conventions.md](../prompts/prompt_shared_conventions.md)）。

| ラベル | 条件（店舗・5値） |
|---|---|
| 好調 | 利益率 ≥ 8.0% |
| 堅調 | 5.0% ≤ 利益率 < 8.0% |
| 要注意 | 0.0% ≤ 利益率 < 5.0% |
| 回復基調 | 利益率 < 0.0% かつ `前月比利益変化率` > 0（赤字だが前月比改善） |
| 不振 | 利益率 < 0.0% かつ `前月比利益変化率` ≤ 0（赤字かつ悪化・横ばい） |

全社は4値（回復基調／不振を「不振」に統合）。「黒字/赤字」は状態ラベルには使わず補足説明のみ。金額は円単位・
桁区切り、比率は小数第1位、欠損は「取得不可」と明記（数値規約も prompt_shared_conventions.md が正本）。

## AppDB レポート文書（コレクション「店舗別損益AI要約」・長文 `analysis_html`）
統合サブWF の AI が生成し、保存 CE `pl_report_api(operation="save")` が AppDB へ書く。保存は破壊的で、
**同一 `doc_key` のサーバー時刻が厳密に古い版だけ**を削除する（[architecture.md](architecture.md) の設計判断を参照）。

- **必須フィールド**（`report_api.py` の `REQUIRED_SAVE_FIELDS`）: `doc_key` / `store_id` / `location_name` / `analysis_html`。空だと保存を拒否（不完全な「最新」で正レポートを巻き添え削除しないため）。
- `generated_at`: 無い／ISO8601 不正なら保存時に UTC ISO8601 を補完（画面は日時降順表示）。
- `doc_key`: 一意キー。全社レポートは **`ALL-{period}-{scenario}`**（`ALL` は全社予約トークン＝個別店舗の `store_id` に割り当て禁止・衝突で片方が恒久削除される）。店舗は `store_id` ベース。
- `report_type`（`store`/`company`）は**ルーティング変数で保存文書には含まれない**（CE は保存時に店舗/全社を区別しない）。

> シナリオ（`シナリオ` 列・`doc_key` の `{scenario}`）は合成データの前提条件ラベル。実データ適用時は、
> 上記の会計レベル・勘定科目種類・会計期間・予算（`予算差異`/`差異率`）・通貨・PDP を顧客の会計定義へ
> 突き合わせてから載せ替えること（[配布品質チェック](distribution-readiness.ja.md)）。
