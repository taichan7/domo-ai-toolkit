# Pro Code スターターアプリ

> 🇺🇸 **English version → [README.md](README.md)**

最小構成の Domo Pro Code アプリの雛形です。マニフェスト経由でバインドしたデータセットを読み込み、プレビューテーブルを表示し、本リポジトリが推奨するデザインシステムを示します。

カスタムアプリの出発点として活用してください。AI エージェントにこの上で実際のワークフローを構築させると良いでしょう。エージェントは `../../../AGENTS.md` のルールに従うはずです (デザインシステム変数を使用、マニフェストバインディングパターンを使用、SDK 経由以外で API を呼び出さない)。

---

## ファイル構成

| ファイル | 役割 |
|---|---|
| `manifest.json` | Domo にアプリの情報を伝える: 名前、サイズ、バインドするデータセット |
| `index.html` | 構造のみ — ヘッダー、統計バー、テーブルカード、アクションカード |
| `styles.css` | すべてのスタイル — ファイル冒頭にデザインシステムの CSS 変数 |
| `app.js` | バインドされたデータセットを読み込み、プレビューテーブルを描画 |

---

## ローカルで実行

Pro Code アプリは Domo の外では完全には動作しません (iframe SDK がデータを提供します)。ただし、`index.html` を直接開いてデザインのプレビューは可能です:

```bash
# macOS
open index.html

# Linux
xdg-open index.html

# Windows
start index.html
```

プレースホルダーデータが表示され、デザインシステムが正しく描画されることが確認できます。

---

## 実データセットへの接続

1. Domo インスタンスでアクセスできるデータセットを選び、UUID をコピーします
2. `manifest.json` を開き、`REPLACE_WITH_DATASET_UUID` を実際のデータセット ID に置き換えます
3. アプリを公開します:

   ```bash
   # Domo CLI がインストール済みの場合
   domo publish
   ```

4. Domo でアプリを開きます。データセットの最初の 50 行が表示されます。

## AI エージェントで拡張する

雛形が実データセットに接続された後、AI エージェントに以下のように依頼できます:

> 「アクションカードの上部に、sage-green の primary ボタンを追加してください。クリックすると `SELECT status, COUNT(*) FROM table GROUP BY status` を実行し、テーブルの隣の新しいカードに結果を棒グラフとして描画してください。」

エージェントは `../../../AGENTS.md` と `../../docs/api-reference.md` を既に読んでいるため、以下の点を守ります:

- デザインシステム変数 (`--sage-green`、`--sandstone` など) を使用し、色をハードコードしない
- URL に生のデータセット ID を埋め込むのではなく、マニフェストバインディング (`mainDs` エイリアス) を使用
- 手動のヘッダー付き fetch ではなく `domo.post('/sql/v1/mainDs', sql, {contentType: 'text/plain'})` を呼び出す
- グリッドレイアウトを尊重 — 絶対配置ではなく実際のグリッドセルに新しいカードを配置

## デザインシステム早見表

すべての色と余白は `styles.css` の冒頭で定義された CSS 変数です。再利用してください:

| 変数 | 使用箇所 |
|---|---|
| `--sage-green` | ポジティブなアクション、成功状態、Primary ボタン |
| `--canyon-red` | エラー、警告、破壊的アクション |
| `--sandstone` | ハイライト、Secondary アクション、アクセント文字 |
| `--alpine-blue` | 情報、リンク、中立的なデータ |
| `--snow-white` | プライマリテキスト |
| `--text-muted` | セカンダリテキスト、ラベル |
| `--glass-bg` | カード背景 |
| `--glass-border` | カード境界線、仕切り |
| `--gap` | グリッドアイテム間の標準的な余白 |

新しい色を追加したくなったら、まず「既存の色のどれかでカバーできないか?」と自問してください。ほぼ常に答えはイエスです。
